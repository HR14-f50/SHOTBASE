# 写真登録仕様

- ログイン済みの index.php アクセスは自分のプロフィール（閲覧会員はアカウント画面）へ転送する。未ログイン時はサービス案内を表示する。
- 写真の選択は追加式。送信前は1枚ずつ削除、全解除が可能。プレビューとファイル名・容量を表示する。
- 1回に最大50枚、1プロジェクト合計200枚。選択時とサーバー側で検証する。
- 1枚20MB未満（20 × 1024 × 1024 バイト未満）。20MBちょうども拒否する。
- JPEG / PNG / WebPを受け付ける。サーバーで実際の画像形式を確認し、拡張子だけでは判断しない。
- 1枚ずつ送信し、各画像の成功・失敗と全体進捗を表示する。未完了だけ再試行できる。
- 送信中・再試行待ちは選択を固定する。再試行は同じバッチID・写真番号を使用し、セッション内で重複登録を防ぐ（24時間）。
- 保存はJPEG、長辺2000px以下、1画像2MB以内。品質を段階的に下げ、必要ならさらに縮小する。
- JPEGのEXIFの向きを補正する。PNG等の透過部分は白背景になる。
- ウォーターマーク再編集用の加工前画像も2MB以内で保存する。表示用画像と合わせ最大約4MB/枚。圧縮前の元ファイルは保持しない。
- 極端な解像度・メモリー不足・デコード失敗はエラーにし、未圧縮の画像を代わりに保存しない。
- 新規アップロード写真は公開で保存する。プロジェクトが下書き・非公開の場合は外部に表示されない。既存写真の状態は変更しない。
- 本人のプロジェクトだけ登録可能。CSRFトークンとプロジェクト所有権を確認する。
- 別タブからの同時登録はDBロックでプロジェクト上限を確認する。失敗時は当該処理で作成したファイルを削除する。

## 実行環境

PHP 8.3以上、PDO MySQL、GD（JPEG / PNG / WebP）、Fileinfo。EXIFはJPEGの向き補正に使用。
1リクエストは1枚なのでPHPの max_file_uploads を50に増やす必要はない。
upload_max_filesize は20M以上、post_max_size はそれより大きく設定する。
現在のMAMPはそれぞれ48M・64M。アップロード処理のメモリー上限は512Mを要求する。

## 検証済み

- 50枚登録、51枚選択制限、51件のバッチ開始拒否。
- 20MBちょうどを拒否、20MB未満を受理。
- JPEG / PNG / WebPの再エンコードと2MB以内の保存、EXIFの向き補正。
- 約11MBのJPEGを約1.69MBへ圧縮。
- 同じ写真番号の再送信で二重登録しないこと。
- 選択追加・プレビュー要素・個別削除・全解除・失敗分再試行はDOMテストで確認。
- ブラウザーで画面表示を確認。ブラウザー自動操作のファイル選択は操作ツールのエラーにより完了せず、実送信はHTTP経由で検証。

デモアカウントには公開4プロジェクト・ダミー画像24枚を登録。画像にはダミーである旨を表示する。
