# SHOTBASE 登録・メール認証仕様

> 2026-09-18更新：メール認証は当面見送りになりました。以下の認証導入手順は過去の検討資料です。現在のプロフィール管理仕様は `profile-controls.md` を参照してください。

## 今回反映した内容

- サイト全体を落ち着いた青系に変更。プロフィール上部のヘッダー画像は非表示。
- ログイン・登録のパスワードに表示／非表示切り替えを追加。
- 登録は「タイプ選択 → 基本情報 → 初期設定 → 確認」の4ステップ。戻って修正可能。
- ユーザー名は半角英数字・アンダースコア20文字以内、ニックネームは20文字以内。共通カウンターで残量を確認。
- パスワードは8〜72文字の半角英数字・記号。大文字・小文字・数字をそれぞれ必須とする。平文パスワードを確認画面や登録途中のセッションに保存しない。
- 投稿ユーザー：任意のアイコン画像（JPEG／PNG／WebP、5MB未満）、10色のテーマ、自己紹介200文字以内。アイコンは256px四方に加工。
- 閲覧専用ユーザー：6種類のプリセットアイコン。公開プロフィールを作成せず、投稿用管理画面・アップロードAPIへのアクセスも制限。
- ステップ3で投稿／閲覧タイプの切り替えが可能。
- 既存アカウントは投稿ユーザーとして維持。

テーマの色・名称は `includes/theme_palette.php` の `profileThemes()` に集約しています。追加したユーザー項目は `migrations/20260918_registration.sql` に記録済み。このMAMP環境には適用済みです。

## メール認証の実装方針（未実装）

現在のPHP・MySQL構成で実装可能です。今回の登録は確認画面で完了すると、そのまま利用できる方式です。メールアドレス欄・認証メール送信・仮登録による利用制限は、まだ有効にしていません。

### 導入手順

1. ステップ2にメールアドレス欄を追加し、形式と重複を検証します。大文字・小文字の扱いなど、アドレスの比較規則を統一します。
2. `users` にメールアドレス、状態（pending／active）、認証日時を追加。別テーブルにユーザーID、認証トークンのハッシュ、有効期限、使用日時を保存します。既存ユーザーはactiveとして移行し、未確認のメールを認証済みとは扱いません。
3. 登録時はpendingとして保存します。暗号学的乱数32バイトからURL用トークンを作成し、DBにはSHA-256ハッシュのみを保存。有効期限は例として24時間とし、設定で変更可能にします。
4. SMTPまたはメール配信サービスのAPIで認証URLを送信します。送信元と認証情報は公開フォルダー外または環境変数で管理します。送信失敗時もpendingのままとし、再送可能にします。
5. URLを開くと確認画面を表示し、本人が「認証する」を押したPOSTで有効化します。メールソフトの自動リンク確認だけで有効化されることを避けます。期限・未使用を検証し、トークン消費とactiveへの更新を同一トランザクションで行います。その後、通常のログインへ案内します。
6. pendingのアカウントはログイン・投稿・公開プロフィール表示を許可しません。再送時は以前のURLを無効化し、アカウント・IP単位で送信回数を制限します。URLやトークンをアプリのログに残さないようにします。

### 導入時に必要なもの

- 利用するSMTPサーバーまたはメール配信サービスの接続情報。
- 送信元メールアドレス。独自ドメインならSPF・DKIMなどの送信設定。
- 公開時のHTTPSサイトURL。認証URLの基点は固定設定し、アクセス元のHostヘッダーから組み立てません。

`localhost` の認証リンクは、そのリンクを開く端末自身を指します。スマホや他の人が認証できる運用には、アクセス可能なサイトURLが必要です。開発中はローカルのメール受信テスト環境を使い、実メールを送らず検証できます。

### 動作確認項目

正常な認証、期限切れ、不正なトークン、二重利用、再送前の古いURL、同時アクセス、送信失敗、未認証ログインの拒否、既存ユーザーの継続利用を確認します。

安全なトークン・期限・一度だけ使える認証の方針は、[OWASPのメール検証ガイド](https://cheatsheetseries.owasp.org/cheatsheets/Email_Validation_and_Verification_Cheat_Sheet.html)を参考にしています。

## 今回の確認結果

投稿／閲覧の両方について、登録完了・ログイン・タイプ切り替え・前のステップへの戻り・文字数制限・パスワード条件・画像登録・テーマ反映を確認済みです。閲覧ユーザーの公開プロフィールと投稿機能へのアクセス拒否も確認しました。確認に作成した一時アカウントは削除し、既存のデモデータは残しています。
